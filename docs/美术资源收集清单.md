# 修仙台 · 美术资源收集清单

用途：收集或生成可用于现有网页的美术素材。现阶段升级视觉，不新增地图、战斗、背包玩法，不修改后端接口。

## 1. 统一画风与交付规则

### 视觉方向

以已选的白发白衣修士为唯一主角，围绕“修士个人档案、修炼卷宗”建立美术风格。参考《鬼谷八荒》的淡彩线稿和纸本质感，使用原创构图与纹样。

- 低饱和、清冷、疏朗；米白纸张、墨灰线条、黛青淡彩，朱砂少量强调。
- 人物沿用现有形象，不重新随机生成角色；其他素材的线条和饱和度向人物靠拢。
- 正文与数字由前端渲染，图片不包含标题、按钮文字、数据或伪文字。
- 按钮、卡片、进度条尺寸随页面变化，应收集可拆分的纹理、边角、端帽；不要求整张固定尺寸的界面截图。
- 现有深色界面与浅色档案卡尚未统一：优先制作可独立叠加的素材，纸张同时准备浅、深两种色阶，最终配色在页面预览后决定。

### 文件要求

下表尺寸是建议的制作尺寸，不是最终网页显示尺寸，也不要求全部做成 8K。

| 类别 | 推荐交付 | 要求 |
| --- | --- | --- |
| 人物、图标、边框 | PNG / WebP 透明底；有 SVG 或分层源文件更好 | 真透明，无白边；不是画出来的棋盘格 |
| 背景 | PNG / WebP，保留高清源图 | 中央低对比，留出正文区域 |
| 纸张 | 无缝 PNG / WebP | 四边能拼接，没有固定阴影和明显污渍 |
| UI 组件 | 独立边角、端帽、底纹；可附分层 PSD | 可拉伸区域与固定装饰分开 |
| 动画 | 先给单帧预览，再给序列帧和帧率说明 | 不替换已经好用的动画，默认不是必需品 |

收集素材时记录来源、作者、授权范围、是否需要署名；付费包保留授权说明。用户提供的主角图目前仅记为“用户提供”，原作者与使用授权尚未核实。

## 6. 可复制的生成提示词

### 通用风格约束

每次生成先附以下约束；角色相关任务同时上传已选原图作为身份参考。

> 为“修仙台”网页制作独立美术素材。东方仙侠，清冷、克制的水墨线稿与低饱和淡彩，细腻纸本质感，米白、墨灰、黛青，朱砂少量点缀。与白发白衣修士插画协调，强调轮廓清楚和小尺寸可读性。原创构图与纹样。不要标题、汉字、数字、伪文字、标志、水印，不要霓虹、厚重金属、水晶按钮、强烈发光或复杂战斗场面。

### A. 主角裁切与适配

> 编辑上传的人物图，保持同一个人的脸型、白发发型、浅蓝眼睛、耳饰、白色服装、姿态和原有线稿不变，不重设计人物。制作头顶到腰部的档案立绘，头顶与发丝留出安全边距。保留白发白衣的细节和半透明细线，提供真实透明背景。不要增加武器、头冠、背景建筑或文字。若源图无法自然补出缺失区域，保留原画范围，不任意延展身体。

头像优先从原图或通过验收的立绘裁切，无需再次生成一张脸。

### B. 无缝宣纸

> 1024×1024 可无缝平铺的细腻宣纸纹理，冷米白底色，轻微自然纤维和极弱色差，均匀照明，适合作为长篇文字背景。四边连续衔接。纯材质，无纸张外轮廓、卷曲、折痕、焦边、污渍、文字、印章和投影。

深色版把“冷米白底色”改为“低对比墨灰黛青底色”，其余保持一致。生成后需实际平铺检查接缝，不能仅凭提示词认定无缝。

### C. 通用卷宗边框

> 单独制作一个横向古籍卷宗面板的装饰边框，画布参考 1024×768，真实透明底，中央完全留空。细墨线双层边缘，四角少量原创云纹，少量暗朱砂点缀。装饰集中在边角，方便拆分成四角与边线后适配不同尺寸。不要卷轴大木轴、纸张内底、人物、标题、文字、按钮和复杂金属雕花。

### D. 单个图标模板

> 制作一个独立的【替换为：古籍 / 玉简 / 星盘 / 阵盘 / 玉佩 / 灵石】图标，256×256，真实透明底。水墨细线勾勒，黛青灰绿淡彩，主体占画面约 75%，居中完整呈现，四周留白，不裁边。剪影简洁，在 32×32 显示时仍能区分。不要底座、文字、发光外框或其他道具。与已通过验收的图标参考保持线宽、饱和度和观察角度一致。

逐个生成图标，不把十二枚图标塞进一张图后勉强切割；先做古籍、玉佩、符箓三枚样本定风格。

### E. 山水背景

> 适合修士个人档案网页的横向山水底图，16:9，参考 2560×1440，清冷低饱和的水墨淡彩。远山层叠、薄雾、淡青灰云海，画面中部约六成保持低细节、低对比，主要山体集中在下部和两侧，方便叠放文字卡片。无人物、无文字、无地图网格、无建筑群、无强烈光束。不是俯视游戏地图，也不是带按钮的完整界面截图。

### F. 档案淡墨底衬

> 横向 1600×600 的透明装饰图层，稀疏黛青灰水墨晕染、淡雾和少量纤细云纹。左侧人物区域有轻微衬托，右侧信息区域大面积留空，边缘自然淡出。仅独立装饰层，不含人物、文字、纸张底色、边框和按钮。用作白发白衣修士档案卡的背景。

## 7. 收集顺序与交付检查

### 最省力的一轮

1. 先处理现有人物裁切和头像。
2. 收集或生成浅色宣纸、深色纸本、通用边框与淡墨底衬。
3. 找一张低对比山水图，在现有页面预览。
4. 先验收三枚图标样本，再补齐整套。
5. 最后处理按钮、进度条、功法册页；可选动效放在后面。

### 每批交付检查

- [ ] 人物和其他素材的饱和度、笔触一致。
- [ ] 透明图有真实 alpha，白衣白发边缘完整。
- [ ] 图标在 32px 清晰，放到浅色、深色底上都检查过。
- [ ] 面板内部留白足够，正文、按钮和数字由网页绘制。
- [ ] 纹理平铺不出现明显拼接线，背景不会干扰正文。
- [ ] 已保留高清源文件；网页发布版另行压缩。
- [ ] 记录素材来源与授权，参考图没有误当作可发布素材。

文件名可沿用本文建议，也可先按 ID 整理交付。最终接入时统一映射到现有 `src/main/resources/static/art/`，无需另外建立游戏引擎用的 `Assets/UI` 目录。
